# کاتالوگ Providerهای آماده در AliasPort

فهرست Providerهای آماده یک فایل مستقل است:

```text
cmd/aliasport/web/provider-presets.json
```

این فایل **کد Go، دیتابیس یا فایل HTML نیست**. فقط یک آرایه JSON است که می‌توانید قالب‌های جدید را به آن اضافه کنید. در برنامه به بخش **ارائه‌دهندگان → افزودن Provider** یا **ویرایش Provider** بروید و روی **انتخاب از فهرست Providerها** کلیک کنید. امکان جست‌وجوی نام، URL و فیلتر نوع API وجود دارد.

با یک کلیک روی قالب، این فیلدها پر می‌شوند:
- `name`: نام Provider
- `base_url`: آدرس API
- `api_type`: پروتکل خروجی

سپس API Key واقعی خودتان را وارد کرده و **ذخیره تغییرات** را بزنید. کلیدها **هرگز** داخل این فایل قرار نمی‌گیرند. در حالت ویرایش، انتخاب یک قالب کلیدهای ذخیره‌شده را تغییر یا حذف نمی‌کند؛ فقط فیلدهای عمومی فرم به‌روزرسانی می‌شوند. انتخاب قالب نیز خودکار ذخیره نمی‌شود.

## اضافه‌کردن Provider جدید

1. فایل `cmd/aliasport/web/provider-presets.json` را باز کنید.
2. یک آبجکت از آرایه `presets` را کپی و در انتهای آرایه Paste کنید؛ بین آیتم‌ها کاما فراموش نشود.
3. پنج فیلد زیر را پر کنید. `id` باید در کل فهرست یکتا باشد.
4. `build.bat` را اجرا کنید تا فهرست جدید در فایل EXE قرار گیرد. با انتشار نسخه جدید، قالب‌ها در انتخابگر ظاهر می‌شوند.

نمونه (به‌عنوان یک **آیتم** داخل آرایه `presets`؛ به‌جای مثال، اطلاعات واقعی سرویس را وارد کنید):

```json
{
  "id": "example-openai",
  "name": "Example AI",
  "base_url": "https://api.example.com/v1",
  "api_type": "openai_chat_completions",
  "description": "سرویس نمونه؛ توضیحات کوتاه برای نمایش در فهرست.",
  "documentation_url": "https://example.com/docs"
}
```

مقادیر معتبر `api_type`:

| مقدار | معنی |
| --- | --- |
| `anthropic_messages` | Anthropic Messages /v1/messages |
| `openai_chat_completions` | OpenAI Chat Completions /v1/chat/completions |

**نکته:** وارد کردن نوع API دیگر (مثل OpenAI Responses) در نسخه فعلی پشتیبانی نمی‌شود. تست‌های Go کاتالوگ را بررسی می‌کنند و در صورت JSON نامعتبر، شناسه تکراری، آدرس نامعتبر یا پروتکل ناشناخته، بیلد را متوقف می‌کنند.

## قالب‌های اولیه

- ZRO: Anthropic Messages و OpenAI Chat Completions
- APInex: Anthropic Messages و OpenAI Chat Completions
- GonkaRouter: Anthropic Messages و OpenAI Chat Completions

این‌ها صرفاً تنظیمات اتصال هستند؛ در دسترس بودن مدل، میزان اعتبار و پشتیبانی عملی از همه ویژگی‌ها با API Key شما و پاسخ واقعی Provider مشخص می‌شود.

## محدودیت‌ها و امنیت

- از کلید، Token، Header محرمانه یا اطلاعات شخصی در `provider-presets.json` استفاده نکنید. API Key فقط در بخش مدیریت Provider و API Keys وارد می‌شود و توسط برنامه رمزگذاری می‌شود.
- `base_url` باید HTTPS معتبر باشد. اگر URL شامل `/v1` باشد، موتور برنامه هنگام ساخت Endpoint از تکرار `/v1/v1` جلوگیری می‌کند.
- این فهرست **آفلاین و همراه EXE** است؛ برای تغییر آن باید سورس را ویرایش و دوباره بیلد کنید. هیچ دیتایی به‌صورت خودکار از سایت‌های خارجی وارد کاتالوگ نمی‌شود.
- کاتالوگ فقط ساخت Provider را سریع‌تر می‌کند؛ سایر بخش‌ها مانند Gateway، قوانین Alias و چرخش API Key بدون تغییر کار می‌کنند.
