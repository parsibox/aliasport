# Gateway and Provider Protocol Conversion

AliasPort keeps **Gateway input protocol** separate from **Provider upstream protocol**. Each Gateway profile stores its own local listening port. Multiple Gateway profiles can be active concurrently, each with a separate local port and client key. A Provider may belong to multiple Gateways, but each Gateway routes only through explicitly associated Providers and its own aliases.

## Supported protocols

| Gateway input | Provider protocol | Support |
| --- | --- | --- |
| Anthropic Messages | Anthropic Messages | Native proxy (including SSE and tools) |
| Anthropic Messages | OpenAI Chat Completions | Request/response/SSE conversion |
| OpenAI Chat Completions | Anthropic Messages | Request/response/SSE conversion |
| OpenAI Chat Completions | OpenAI Chat Completions | Native proxy (including SSE and tools) |
| OpenAI Responses API | Any | **Not implemented**; deliberately not selectable |

### Example: Claude Desktop → APInex OpenAI endpoint

- Provider name: `APInex`
- Provider URL: `https://api.apinex.bond/v1`
- Provider API type: `OpenAI Chat Completions`
- API key: one or more APInex `sk-apx...` keys saved in the **API Keys** section.
- Gateway name: `Claude Desktop`
- Gateway input type: `Anthropic Messages`
- Gateway local port: `18765`
- Alias: `claude-sonnet-5-5` → `claude-sonnet-5.5` (or any model ID that the provider actually supports)
- Client base URL in Claude Desktop: `http://127.0.0.1:18765`
- Client credential: the **local Gateway client key**, not the APInex key.

Claude Desktop sends an Anthropic Messages request. AliasPort chooses the alias's Provider and model, converts the body into OpenAI Chat Completions, forwards the call to `https://api.apinex.bond/v1/chat/completions`, converts the response (including SSE text/tool deltas), and returns an Anthropic Messages response.

### Example: OpenAI SDK → ZRO Anthropic endpoint

- Provider name: `ZRO`
- Provider API type: `Anthropic Messages`
- Provider URL: `https://zro.moonmath.ai`
- Gateway input type: `OpenAI Chat Completions`
- Gateway local port: `18766`
- Alias: `gpt-4o` → `deepseek-v4.1-flash` (example; target model must exist upstream)
- Client base URL: `http://127.0.0.1:18766/v1`
- Local client key: generated by AliasPort or set in the Gateway editor.

OpenAI SDKs call `POST /v1/chat/completions`, and AliasPort converts to upstream Anthropic `POST /v1/messages`.

## Per-profile proxy ports

- Each gateway has editable **Input Protocol** and **Proxy Port** fields. The settings page no longer contains a global proxy port.
- Startup listens on **all active Gateway profiles' ports**.
- Clicking **Run** starts that Gateway without stopping others. An occupied port produces an error without changing any running Gateway.
- Clicking **Stop Proxy** stops only the selected Gateway without closing the management UI or other Gateway listeners.
- Editing an active profile's port acquires the replacement port before switching over. The previous listener stops accepting new connections; in-flight SSE requests are allowed a bounded graceful shutdown.
- Management UI remains on `127.0.0.1:8787` by default and is configured separately via the `-admin` CLI flag.
- Existing databases migrate automatically: Anthropic protocol and port `18765` remain defaults, and old Provider/Gateway associations are preserved from their Aliases.

## Conversion capabilities and limitations

Supported in both directions:
- System/developer instructions and regular user/assistant text
- Supported multimodal image parts (base64 and URL; provider model capabilities still apply)
- Client-side function tools, tool calls, tool results and common tool-choice policies
- Generation limits, temperature and stop sequences
- Non-streaming response envelopes, stop reasons and reported token usage
- SSE text deltas and tool-use deltas

**Important limitations:**
- Provider-specific extended thinking, MCP/server tools, audio, structured response formats, reasoning controls, prompt cache directives and some specialized fields are **not automatically equivalent**. Selected incompatible request features produce an explicit 422 error rather than silently claiming equivalent behavior.
- Anthropic `/v1/messages/count_tokens` has no direct OpenAI Chat Completions equivalent; such requests receive an explicit 501 for an OpenAI provider. Native Anthropic→Anthropic calls continue to pass through.
- OpenAI tool-call argument fragments may interleave. Conversion buffers those fragments until the tool call is complete, then emits sequential Anthropic tool blocks. Text is still forwarded progressively.
- Provider-specific model capability verification and OpenAI Responses API translation require additional development.
- The `*` alias remains a fallback; an enabled exact alias wins.
- Multiple upstream API keys and billing-only failover keep working across the protocol matrix.

```bat
git pull origin main
build.bat
```

The included tests exercise both conversion directions, tool calls, SSE streaming, URL normalization with and without `/v1`, independent gateway ports, profile switching, and default migration. Real APInex/ZRO credentials are never included in the repository or tests.
