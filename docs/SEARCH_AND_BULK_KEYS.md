# فیلترها و حذف گروهی API Keyها

## جست‌وجو در لیست‌ها

این فیلترها داخل پنل، بدون ارسال درخواست مجدد به Provider خارجی، روی اطلاعات بارگذاری‌شده کار می‌کنند:

| صفحه | فیلترها |
| --- | --- |
| ارائه‌دهندگان | جست‌وجوی نام، Base URL و نوع API |
| پروفایل‌های Gateway | نام، پروتکل و پورت |
| کلیدهای API | جست‌وجوی نام کلید و اثر انگشت؛ فیلتر Provider |
| Model Aliases | جست‌وجوی مدل ورودی/مقصد و نام Provider/Gateway؛ انتخاب Provider، Gateway و وضعیت فعال/غیرفعال |
| تاریخچه درخواست‌ها | جست‌وجوی مدل، وضعیت HTTP و زمان |

انتخاب **همه موارد** در جدول کلیدها یا Aliasها فقط روی **ردیف‌های قابل‌مشاهده پس از فیلتر** اعمال می‌شود. با تغییر فیلتر، انتخاب‌های قبلی پاک می‌شوند تا آیتم مخفی ناخواسته حذف یا تغییر داده نشود.

## میانبرها در مدیریت Providerها

در سطر هر Provider:

- **ایجاد کلید API**: فرم ساخت کلید را باز می‌کند و Provider همان سطر از پیش انتخاب شده است.
- **ایجاد قانون Alias**: فرم Alias را باز می‌کند و Provider همان سطر را به‌عنوان مقصد از پیش انتخاب می‌کند. Gateway و مدل مقصد همچنان قابل انتخاب هستند.
- **نمایش Aliasها**: صفحه Model Aliases را باز می‌کند و فیلتر Provider را همان Provider قرار می‌دهد.

کلید API واقعی را باید از سایت Provider بگیرید؛ فرم جدید صرفاً کلید صادرشده را در دیتابیس AliasPort ثبت می‌کند.

## حذف گروهی کلیدهای API

در صفحه **کلیدهای API** از چک‌باکس هر ردیف یا گزینه انتخاب همه استفاده کنید. تعداد کلیدهای انتخاب‌شده در نوار بالای جدول نمایش داده می‌شود. با زدن **حذف گروهی کلیدهای API**، تعداد کلیدها و تعداد Providerهای درگیر به شما اعلام و تأیید صریح درخواست می‌شود.

پس از تأیید، کلیدهای انتخاب‌شده به‌صورت **تراکنشی** حذف می‌شوند. اگر شناسه‌ای نامعتبر یا حذف‌شده باشد، درخواست به‌طور کامل رد شده و هیچ کلیدی حذف نمی‌شود. سایر کلیدها و Providerها دست‌نخورده می‌مانند.

**هشدار:** اگر آخرین کلید قابل استفاده یک Provider را حذف کنید، اتصال به آن Provider تا ایجاد API Key جدید ممکن نخواهد بود.

## API

`POST /api/keys/bulk` روی پورت مدیریت، با بدنه:

```json
{
  "action": "delete",
  "ids": ["0123456789abcdef01234567", "89abcdef0123456701234567"]
}
```

پاسخ موفق:

```json
{"action":"delete","affected":2}
```

محدودیت: ۱ تا ۵۰۰۰ شناسه یکتا در یک درخواست. عملیات `enable` و `disable` برای API Keyها در این نسخه اضافه نشده است؛ فقط **حذف گروهی** درخواست شده و پیاده‌سازی شده است.

مدیریت دستی تک‌کلید، اولویت، فعال/غیرفعال و بازنشانی Billing بدون تغییر باقی می‌ماند.
